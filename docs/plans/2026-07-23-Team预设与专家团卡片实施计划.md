# Team 预设与专家团卡片实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在现有“新建团队”弹窗中增加“助手 / 专家团”切换，让用户可以预览、管理并一键调用可复用的普通 Team 预设。

**Architecture:** 不新增侧边栏入口、独立路由或新的 Team 运行页面。扩展现有 `TeamCreateModal`：助手模式保持现状，专家团模式显示预设列表和介绍卡片；调用预设后切回助手模式，并用预设填充现有成员、队长和模型选择状态。预设的简介只用于卡片展示，不新增 Team 通信协议或复杂运行时上下文注入。

**Tech Stack:** AionUi React/TypeScript、Arco Design、IPC bridge、SWR、i18n、Vitest；AionCore Rust、Axum、SQLite migrations、现有 Team service/API。

---

## 1. 已确认的产品交互

### 入口位置

不修改侧边栏。

入口位于现有文件：

`packages/desktop/src/renderer/pages/team/components/TeamCreateModal.tsx`

左侧“所有助手”标题右侧增加模式切换：

```text
[助手] [专家团]
```

默认进入“助手”模式，现有搜索、添加成员、队长选择和创建流程保持不变。

### 专家团模式

切换后：

- 左侧显示专家团列表；
- 右侧显示当前选中专家团的介绍卡片；
- 顶部提供“新建专家团”；
- 每个列表项提供“调用”按钮和更多菜单；
- 更多菜单提供“编辑”和“删除”。

### 一键调用

点击列表或卡片中的“调用此专家团”：

```text
读取预设
  → 校验成员是否仍可用
  → 切回“助手”模式
  → 填充现有 TeamCreateModal 状态
  → 用户可调整成员、队长、模型和工作区
  → 点击现有“创建团队”按钮
```

不绕过现有创建确认，也不直接创建 Team。

### 介绍卡片

卡片展示：

- 图标、名称、分类；
- 团队简介；
- 擅长领域标签；
- 队长和成员列表；
- 示例任务；
- “调用此专家团”按钮。

卡片内容由用户在预设编辑器中填写，简介和成员信息与卡片保持一致。

## 3. 数据模型

### TeamPreset

```ts
type TeamPreset = {
  id: string;
  user_id: string;
  name: string;
  icon?: string;
  category?: string;
  description: string;
  expertise_tags: string[];
  example_prompts: string[];
  leader: TeamPresetMember;
  members: TeamPresetMember[];
  version: number;
  created_at: string;
  updated_at: string;
};
```

### TeamPresetMember

成员选择复用现有 Team Assistant 输入，不新建另一套 Assistant：

```ts
type TeamPresetMember = {
  assistant_backend: string;
  assistant_id?: string;
  model?: string;
  assistant_name: string;
  role: string;
  order: number;
};
```

约束：

- `leader` 必须属于 `members`；
- `assistant_id` 或模型不可用时，列表和卡片显示缺失状态；
- 调用时不得静默丢弃缺失成员，必须提示用户替换；
- 预设创建 Team 时保存成员配置快照；
- 后续修改预设不影响已经创建的 Team；
- `version` 只为后续升级提示预留，第一版不自动升级已有 Team。

## 8. 验收标准

- 现有新建团队弹窗中可以切换“助手 / 专家团”；
- 不修改侧边栏和现有 Team 导航；
- 点击专家团可以看到 WorkBuddy 风格介绍卡片；
- 列表和卡片都可以一键调用；
- 可以在同一页面新增和删除专家团；
- 调用后复用现有成员、队长、模型和工作区选择逻辑；
- 缺失成员不会被静默忽略；
- 创建后的 Team 完全复用现有运行机制；
- 旧 Team 和普通助手创建流程不受影响。
