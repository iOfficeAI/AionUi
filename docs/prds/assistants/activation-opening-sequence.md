# 首启开屏三页动画 (F-OPEN)

> 本文档定义新用户第一次打开 AionUi 时，那段三页开屏动画怎么呈现。
>
> 这三页由**用户本机的真实扫描结果**驱动：扫到什么工具、有没有工具，决定了后两页的内容与主角。它不是一段固定的演示视频，而是根据用户电脑动态组装的开场。
>
> **几个名词**：
>
> - **AionCLI**：AionUi 出厂自带的一个 Agent，不用装、开箱即用，从一开始就在。
> - **外部工具（CLI Agent）**：用户自己装在本机的命令行 AI 工具，如 Claude Code、Codex、Gemini CLI。开屏第一页扫描、识别的就是这些。
> - **助手**：一个有名字、能记住你、越用越懂你的角色，例如"Patrick · 写作助手"。
> - **工具与助手的关系**：工具是底层引擎（Claude Code 等），可替换；助手骑在工具之上，有名字、会沉淀你的偏好。一个助手底层用哪个工具可以换，换了工具，助手和它记住的东西还在。
>
> **编号约定**：`F-OPEN-NN`，OPEN = Opening（开屏）。

## 一、这段动画要回答什么

用户为"聚合我的 CLI 工具"而下载 AionUi，打开却是个空白输入框——他期待的"识别我的工具"没在第一眼兑现，产品"能养出越用越懂我的助手"这个价值也没被讲出来。

开屏三页，用一段连贯的动画补上这两件事，且用用户本机真实的东西当主角：

1. **第一页**：它真认识我装的工具。
2. **第二页**：这些工具，都能变成我专属的助手。
3. **第三页**：助手会记住我，底层工具还能随便换、不丢。

---

## 二、三页共用的两个变量

整段动画由两个变量驱动，由第一页的扫描结果自动确定，后两页跟着变。

**变量 A：有没有扫到外部工具**

| 情况 | 触发 | 后续 |
| --- | --- | --- |
| **有** | 扫到 ≥1 个外部工具 | 三页以扫到的工具为主角 |
| **无** | 一个外部工具都没扫到 | 主角换成内置 AionCLI，文案转为"以后可持续接入" |

**变量 B：主角工具**

- 第二、三页动画里那个"变成助手 / 记笔记"的主角工具。
- 取值：有外部工具时，取扫到的第一个外部工具（如 Claude Code）；没有时，取内置 AionCLI。
- 主角的名字与图标来自扫描结果，随用户实际装的工具而变——用户装的是 Codex，主角就是 Codex。

## F-OPEN-01 第一页：扫描并点亮你的工具

**要让用户感到**：我还没干嘛，它就已经认识我电脑里的 AI 工具了。

**画面与动作**

1. 进入即开始扫描本机的外部 AI 工具，显示"正在扫描本地的 AI 工具…"和一个进行中的转圈指示。
2. 内置的 AionCLI 一开始就在列表里，标注"自带"，让用户从第一秒就不是空手。
3. 扫到的每个外部工具逐个点亮：一条一条出现、打上勾，呈现"正在被识别、接管"的过程感。
4. 扫描结束，指示变为"完成"，给出数量汇总（如"共 4 个已就位"，含内置 AionCLI）。
5. 扫描完成后，标题与副文落定为结论态。

**文案方向**

- **有外部工具**：你装的工具，它都认识；不用重新配置，直接接管。
- **无外部工具**：AionCLI 已自带、现在就能用；以后你装了 Claude Code、Codex 之类的工具，会随时被认出、接进来。

**验收标准**

- [ ] 进入第一页即执行对本机外部工具的真实扫描
- [ ] AionCLI 始终作为"自带"项呈现，不计入"扫描发现"
- [ ] 扫到的外部工具逐个点亮，而非一次性出现
- [ ] 扫描完成后显示数量汇总（含内置 AionCLI）
- [ ] 有 / 无外部工具时，标题与副文走对应文案

## F-OPEN-02 第二页：工具派生出一群助手

**要让用户感到**：这些不只是工具——它们能变成一个个专门帮我干活的助手，而且不止我装的那几个，这里有一大批。

**画面与动作**

1. 主角工具先作为一个"工具"出现，通过一条连线派生出一个同名"助手"（标注"你的助手"）。这条"工具 → 助手"的连线是本页主线：助手是从工具长出来的。
2. 在这个主角助手旁边，一排专家助手依次扩散出现。
3. 专家覆盖研发与办公两类，例如：代码开发、测试、UI 设计、写作、数据分析、调研。这是"AionUi 内置的一批各有专长的助手"的示意。
4. 主角随变量 B 变化：主角是 Claude Code 就从 Claude Code 派生，是 AionCLI 就从 AionCLI 派生；周围那排专家两种情况下一致。

**文案方向**

- 传达"用着用着，工具就长成为你量身定制的专家"的演化感——是"能变成助手"，而非"就是助手"。

**验收标准**

- [ ] 主角工具通过连线派生出一个同名助手，工具与助手的先后关系清晰可见
- [ ] 一排专家助手依次出现，排布整齐、互不重叠
- [ ] 专家同时覆盖研发类与办公类
- [ ] 主角随变量 B 变化，随用户实际装的工具而定

## F-OPEN-03 第三页：助手记住你，换工具也不丢

**要让用户感到**：我教它的东西，它真记住了；而且这是记在"助手"身上的，底层工具随便换，都不会丢。

**助手与工具是两个身份，分开呈现**

- 笔记本的主人是一个有名字的助手（示意"Patrick · 写作助手"），头部显示它的名字与头像，它是"记住你"的主体。
- 底部的"当前工具"是这个助手底层正在用的 CLI，可切换。

**画面与动作**

1. 一句用户的话（示意"记住：以后写稿都别用感叹号"）出现，助手把它记进自己的笔记本，笔记逐行写入、越写越厚。
2. 底部"当前工具"持续按节奏切换（如 Claude Code → Codex → Gemini，循环往复），而上方的助手身份与笔记内容始终不变。用"工具在换、笔记不动"的对照，让"换工具也不丢"一眼可见。
3. 结论交给页面主标题正面表达，画面本身说明"东西还在"。

**两种情况下的"当前工具"切换内容**

- **有外部工具**：在用户真实拥有的工具间循环（如 Claude Code / Codex / Gemini）。
- **无外部工具**：当前工具是 AionCLI；其余工具以"待接入"的弱化（灰 / 虚线）态参与循环，表示以后接入了也一样、笔记跟着走，而不是假装用户已经有这些工具。

**文案方向**

- 正面主张，如"助手越用越懂你，换个工具也不丢"。
- 只传达"东西还在"这一结果，不去解释它存在哪里。

**验收标准**

- [ ] 笔记本主人显示为有名字的助手，不显示成工具名
- [ ] 用户的一句话被写入笔记本，逐行累积
- [ ] 底部"当前工具"持续循环切换，期间助手身份与笔记内容不变
- [ ] 无外部工具时，其它工具以"待接入"态参与，不呈现为已拥有
- [ ] 笔记内容与助手的专长匹配（写作助手记写作偏好）

## F-OPEN-04 导航、跳过与"仅首次"

**期望行为**

- 三页有页码指示、可前后切换；提供随时可点的「跳过」；末页主按钮为「开始使用」，点击进入首启欢迎界面。
- 两种情况都完整走完三页：没有外部工具的用户同样看第二、三页（主角换成 AionCLI）。
- 整段开屏只在用户第一次打开 App 时出现一次。正常走完、点「跳过」、或中途关闭 App，都计为"已看过、下次不再出现"。

**验收标准**

- [ ] 三页可前后切换、有页码指示、可随时跳过
- [ ] 两种情况都完整呈现三页
- [ ] 末页主按钮进入欢迎界面
- [ ] 开屏仅首启出现一次（走完 / 跳过 / 中途关闭均计为已看过）

## F-OPEN-05 兜底与异常

| 场景 | 期望 |
| --- | --- |
| **扫描耗时较长** | 第一页保持"扫描中"的进行态，不空屏干等；超过合理时长可先按"暂未发现外部工具"呈现，后台若又扫到再补充。 |
| **扫描失败 / 无权限** | 按"无外部工具"处理：AionCLI 已自带、照样能开始，必要时给一句轻提示。 |
| **一个外部工具都没有** | 走"无外部工具"的一条线，不停留在空结果。 |
| **扫到很多工具（如 6 个以上）** | 第一页列表有合理的呈现上限或滚动，避免铺满整屏；主角仍取其一。 |
| **用户中途跳过 / 关闭** | 计为已看过，下次不再出现。 |

**验收标准**

- [ ] 扫描慢 / 失败 / 无权限时有兜底，不空屏
- [ ] 无工具、扫到很多工具都有合理呈现
- [ ] 各兜底路径都能顺利走到"开始使用"

## 三、整体时间轴

> 时序为体验节奏参考，具体毫秒数由设计打磨。

```
第一页  [进入] → 扫描中(转圈) → 外部工具逐个点亮(依次) → 完成+数量汇总 → 标题落定
         ↑ 内容由真实扫描结果决定；有/无工具在此分流

第二页  [进入] → 主角工具出现 → 连线派生出"主角助手" → 一排专家依次扩散出现
         ↑ 主角随扫描结果而变

第三页  [进入] → 用户那句话出现 → 逐行写入助手笔记本
              → 底部"当前工具"持续循环切换，助手与笔记始终不动（循环到离开本页）
```

## 四、待技术确认

1. **能扫描识别哪些外部工具、扫描耗时、权限要求**：决定第一页能不能成立。
2. **主角工具的选取规则**：扫到多个时"第一个"按什么排序，或是否让用户在第一页点选主角。
3. **"换工具不丢"的真实性**：这段动画对外承诺"换底层工具、助手记忆不丢"，需确认与实际实现一致（记忆绑在助手、而非具体工具或会话上）；做不到则调整这一页的表述。
4. **逐字文案与视觉动效规格**：三页最终文案、配色、扫描与扩散的动画参数，作为独立的设计与内容课题打磨。
5. **"仅首次"的持久化维度**：以设备还是账号为准，是否允许在设置里重看。
