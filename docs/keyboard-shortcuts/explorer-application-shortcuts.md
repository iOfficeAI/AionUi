# Explorer Application Shortcuts Review

审查范围来自 `C:\Projects\AionUI\raw\shortcuts_function_merged.md` 中三组候选：

- 全局与应用
- 会话切换与导航
- 诊断、开发与高级功能

本次只审查 AionUI 现有注册函数、模块逻辑和可用性，不改业务代码。结论以当前 `packages/desktop` 代码为准。

## 总体发现

- AionUI 目前没有统一 command registry / shortcut registry。快捷键分散在 React hook、Electron menu role 和 `before-input-event` 中。
- 明确的 renderer 快捷键注册点主要有：
  - `packages/desktop/src/renderer/hooks/ui/useConversationShortcuts.ts`
  - `packages/desktop/src/renderer/pages/conversation/components/ConversationTitleMinimap/useMinimapPanel.ts`
  - `packages/desktop/src/renderer/pages/conversation/GroupedHistory/ConversationSearchPopover.tsx`
  - `packages/desktop/src/renderer/components/layout/Sider/index.tsx`
  - `packages/desktop/src/renderer/pages/conversation/Preview/hooks/usePreviewKeyboardShortcuts.ts`
- Electron 主进程没有发现 `globalShortcut`。应用级菜单使用 Electron role 提供默认刷新、强刷、DevTools、缩放等快捷键。
- 已有且可用性较高的候选：`Ctrl+T` 新建会话、`Ctrl+Tab` / `Ctrl+Shift+Tab` 切换可见会话、`Ctrl+F` 当前聊天搜索、`Ctrl+Shift+F` 全局聊天搜索。
- 多数全局应用类候选已有 UI 或路由，但没有快捷键入口；若后续实现，建议先补统一命令层，再接快捷键、命令面板和设置页自定义。

## 建议后续顺序

1. 建立统一命令定义：命令 ID、标题、默认快捷键、平台、上下文、执行函数。
2. 先接入低风险且已有动作的快捷键：设置、侧栏、路由返回/前进。
3. 保留并文档化现有会话快捷键：`Ctrl+T`、`Ctrl+Tab`、`Ctrl+Shift+Tab`、`Ctrl+F`、`Ctrl+Shift+F`。
4. 对诊断和开发能力只做命令面板/设置页入口，避免给普通用户默认全局键。
5. 实现冲突检测前，不建议新增 `Ctrl+Shift+R`、`Ctrl+Shift+S`、`Ctrl+Shift+A`、`Ctrl+W` 这类高冲突或高风险绑定。
