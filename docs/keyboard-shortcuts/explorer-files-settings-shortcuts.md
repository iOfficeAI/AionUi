# Explorer / Files / Settings Shortcuts Review

审查对象：`C:\Projects\AionUI\raw\shortcuts_function_merged.md` 中“文件、项目与工作区”“外观、语言与主题”“设置页/快捷键设置 UI”相关候选快捷键。

审查范围：AionUI 桌面端现有注册函数、模块入口、页面结构和可用性。本文只做现状审查与建议，不改业务代码。

## 总体结论

- AionUI 目前没有统一 command registry / keybinding registry。现有快捷键分散在 renderer `keydown` hook、Electron 主进程 `before-input-event`、Electron 菜单 role、组件局部键盘事件里。
- 本组候选里，真正已经注册为默认快捷键的主要是：`Ctrl/Cmd+T` 新建会话、`Ctrl+Tab` / `Ctrl+Shift+Tab` 切换会话、`Ctrl/Cmd+F` 当前聊天搜索、`Ctrl/Cmd+Shift+F` 全局聊天搜索、`Ctrl/Cmd+S` 预览保存、`Ctrl/Cmd +/-/0` UI 缩放、Electron 菜单自带刷新/强刷/编辑类 role。
- 文件/工作区功能模块较完整，但多数只有 UI 按钮或右键菜单，没有默认快捷键。`Ctrl+P` 搜索文件、`Ctrl+O` 打开项目/文件夹、`Ctrl+Shift+E` 切换工作区面板、`Ctrl+,` 打开设置都尚未看到注册。
- 设置页已具备页面式 `/settings/*` 信息架构和旧的 modal 式设置组件；快捷键设置页更适合新增为页面式设置项，放在“App”分组中，建议在“显示”后、“系统”前。

## 设置页结构与快捷键设置页位置

当前页面式设置路由在 `packages/desktop/src/renderer/components/layout/Router.tsx`：

- `/settings/model`
- `/settings/assistants`
- `/settings/agent`
- `/settings/capabilities`
- `/settings/display`
- `/settings/webui`
- `/settings/pet`
- `/settings/system`
- `/settings/about`
- `/settings/ext/:tabId`

设置侧栏顺序来自 `packages/desktop/src/renderer/pages/settings/components/SettingsSider.tsx` 的 `BUILTIN_TAB_IDS`：

```ts
['agent', 'model', 'assistants', 'capabilities', 'display', 'webui', 'pet', 'system', 'about'];
```

分组标题也在同文件中定义：

- `agent` 前显示 `settings.groupAiCore`
- `display` 前显示 `settings.groupApp`
- `about` 前显示 `settings.groupAbout`

因此，快捷键设置页建议：

1. 新增 `/settings/shortcuts`，作为页面式设置页，不放进旧 `SettingsModal` 的首批范围。
2. 在 `BUILTIN_TAB_IDS` 中放在 `display` 后、`webui` 前，归入 `settings.groupApp`。理由：快捷键是应用级交互偏好，和显示、WebUI、系统同属 App 设置；但它不是纯外观，不应塞进 DisplaySettings。
3. 移动端顶部设置导航由 `SettingsPageWrapper.getBuiltinSettingsNavItems()` 使用同一批内置项生成，也需要同步新增 `shortcuts` item。
4. 需要新增路由、页面组件、i18n key、图标，以及后续 keybinding 存储 key。扩展设置 tab 的 anchor 逻辑已经支持插入内置项前后，新增 `shortcuts` 后也要考虑扩展是否可能 anchor 到该 tab。

若第一阶段只做“快捷键总览”，可以先用 `/settings/shortcuts` 展示不可编辑表格。若直接做“自定义快捷键”，建议先完成：

- 命令定义：`id`、标题、分类、默认快捷键、平台差异、作用域。
- 作用域：全局、会话、工作区、预览、Webview、输入框。
- 冲突检测：系统保留、Electron role、浏览器默认、SendBox/编辑器、Webview。
- 持久化：用户覆盖、禁用、恢复默认。

## 优先级建议

| 优先级 | 功能                             | 原因                                                   |
| ------ | -------------------------------- | ------------------------------------------------------ |
| P0     | `Ctrl+,` 打开设置                | 跨应用习惯强，现有路由入口成熟。                       |
| P0     | `Ctrl+Shift+E` 切换工作区面板    | 已有事件和折叠逻辑，实现成本低，文件工作区使用频率高。 |
| P1     | `Ctrl+P` 搜索当前工作区文件      | 语义稳定，但需要外层触发并聚焦 workspace 搜索。        |
| P1     | `/settings/shortcuts` 快捷键总览 | 是后续自定义快捷键的前置，也能降低用户发现成本。       |
| P2     | `Ctrl+O` 选择/打开项目           | 功能存在但语义需按页面上下文拆分。                     |
| P2     | `Ctrl+U` 附加/上传文件           | 需要 SendBox 与 Workspace 的上下文分派。               |
| P3     | 主题/语言快捷键                  | 低频设置，不建议默认绑定，适合命令面板。               |

## 关键风险

- 没有统一快捷键注册层时继续新增 `window.addEventListener('keydown')` 会加剧冲突和不可发现性。
- `Ctrl+P`、`Ctrl+O`、`Ctrl+F` 等常见键在 WebUI/browser、Electron、编辑器、预览、Webview 里含义不同，必须限定运行时和焦点上下文。
- 工作区目前既是“新建会话选择的项目目录”，又是“会话 extra.workspace”，不是独立 Project 实体；“切换工作区”“新建工作区”“下一个项目”不宜在模型未统一前默认绑定。
- 旧 `SettingsModal` 和新 `/settings/*` 页面并存。快捷键入口应优先绑定页面式设置，避免两个设置系统继续分叉。
