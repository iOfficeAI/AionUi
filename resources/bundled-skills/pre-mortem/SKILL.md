# Pre-Mortem

A pre-mortem is the inverse of a post-mortem: instead of explaining a failure after it happened,
you **assume it happened** (at a chosen future date) and reason backward through the chain of
events and decisions that killed it. It escapes the optimism of the people who built the plan and
surfaces the real risks while there is still time to fix them. The output is not a list of worries
— it is **a set of concrete changes to the decision the user is about to make.**

## When to use
- Before committing to a strategy, launch, campaign, sales/marketing plan, hire, pricing change, or big spend.
- When a plan "feels right" — that is exactly when blind spots hide.
- Whenever the user asks "what could go wrong", "will this work", "poke holes in this", or wants a stress-test.

## The method
1. **Set the scene.** Pick a concrete future date (e.g. "6 months from now"). State it flatly:
   *"It is [date]. [The plan] has FAILED."* No hedging — assume failure and explain HOW.
2. **Adopt a hostile stance.** Be the unsentimental forensic analyst, not the cheerleader. The
   value is in the uncomfortable truths. If you catch yourself softening, that is the signal to sharpen.
3. **Run multiple independent lenses** when the plan is non-trivial — each attacking from ONE distinct
   angle, not the same worry rephrased. Useful lenses: demand/market · execution & founder-capacity ·
   competition/timing · money/runway · trust/incident · activation/onboarding · technical-foundation ·
   pricing/segment-fit. (Diverse angles beat redundancy.)
4. **Write the failure-chain.** An ordered chain of events + decisions from now → the failure date.
   Be specific: name the wrong decisions and the moment it became unrecoverable.
5. **Earliest warning sign** — the leading indicator that was ignored (something you could watch for in real life).
6. **Root decision error** — the single decision, made now or soon, that seeded the failure.
7. **What we should have done** + **the concrete change to make TODAY.**
8. **Probability + severity** — honestly (recoverable / serious / fatal).
9. **Synthesize:** the cross-cutting patterns (what shows up across multiple lenses = the real
   killers), the single most-likely death (usually the *quiet* one, not the dramatic one), and the
   prioritized changes to today's decisions.

## Output
- The failure-chain(s) + a small table (lens · how it died · probability · severity).
- The cross-cutting killers (the risks that appear across several lenses).
- **How it changes the decision the user should make now** — a pre-mortem that changes no current decision was theater.
- The **kill-criteria / leading indicators** to watch, so the user can detect the failure early and act before it is fatal.

## Rules
- Honesty over comfort. Soft criticism is worthless.
- Ground it in the SPECIFIC plan — read the actual plan/context first; never generic risks.
- The deliverable is the change to today's decision, not the catalogue of fears.
